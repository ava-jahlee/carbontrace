# Primary source `note` 표준

> `PrimarySource.note` 필드 작성 규칙 · 참고자료

---

## 필드 목적

`note` 는 감사자가 Cell 팝오버에서 보는 텍스트. 원문서 카드의 마지막에 인용문 형태로 렌더된다.

**주 독자**: 제3자 검증기관 · 심사원 · 감사자
**부 독자**: 사업자 실무자 · 내부 컨설턴트

개발자용 주석·slang·감정 표현 금지.

---

## 첫 문자 규칙 (매우 중요)

| 시작 문자 | 의미 | UI 처리 |
|---|---|---|
| `⚠` | 원본 오작성 · 확인 필요 · 정정 대안 존재 | Cell 에 warning 배지 · 카드 노란 강조 |
| (일반 문자) | 참고 · 설명 | 일반 렌더 |

**`⚠` 는 성숙도가 낮다는 뜻이 아니라 "감사자가 반드시 확인해야 한다" 는 뜻.**
`verified` 원문서에서도 특정 값이 `⚠` note 를 가질 수 있다 (예: 원본 xlsm 이 값을 잘못 옮긴 경우).

---

## 톤 · 문체

1. **한국어. 문장. 마침표.**
2. **사실만.** 사업자·저자를 비난하는 표현 금지 ("잘못 넣음" → "뒤바꿔 옮김").
3. **단정어 vs 추정어**를 명확히:
   - 확정: "~이다.", "~와 일치한다.", "원문서에서 재확인 완료."
   - 추정: "~로 추정.", "표 참조 미확인.", "원문서 재확인 대기."
4. **약어**: `T1/T2/T3` · `EF` · `NCV` · `GWP` 는 그대로. 그 외 (예: SNG · CDM) 는 풀어 쓰기.

---

## 문장 구조 · 3부 구성

```
[상황·값 요약]. [원문서 위치 참조]. [현재 처리 방식 또는 근거].
```

### 예시별 해석

**verified — 문서·값 완전 검증**
```
K-ETS 별표 12 표 A · 아역청탄 tC 24.83 kg/GJ. 저자가 24.83 × 44/12 × 1000 으로 CO2 배출계수 91,043.33 kgCO2/TJ 파생.
```
- 1부: "K-ETS 별표 12 표 A · 아역청탄 tC 24.83 kg/GJ" — 값·위치
- 2부: (생략 · 1부에 결합)
- 3부: "저자가 ... 파생" — 값이 어떻게 도출됐는지

**documented — 문서·페이지 참조**
```
GIR 2022년 승인 · 2023년 공표 국가고유 배출계수. 표 A · 12행 (경유). 원문서 표 값 재확인 대기.
```

**asserted — xlsm 값이지만 원문서 확인 필요**
```
xlsm 원본 사용값. GIR 2017년 승인 판 (2018.1 공표 추정) 으로 추정. 원문서 표 참조 미확인.
```

**asserted + warning — 원본 오작성**
```
⚠ xlsm 원본 오작성. 저자가 등유·항공유 값을 뒤바꿔 옮김. 정확한 K-ETS 별표 12 등유 = 19,969 kgC/TJ (73,153 kgCO2/TJ). xlsm-corrected 프로파일에서 자동 정정.
```

**pending — 조사 중**
```
xlsm 원본 값. 원문서 미조사. 조사 대기.
```

## 필수 정보 · 체크리스트

`note` 를 작성할 때 다음을 포함하려 노력:

- [ ] 원문서 발행처 · 표기 (예: "K-ETS 별표 12" · "GIR 2022.1 공표" · "IPCC 2006 Vol.2 Ch.2")
- [ ] 표 · 행 · 페이지 위치 (가능하면)
- [ ] 값의 단위 (숫자만 있으면 안 됨)
- [ ] 값의 도출 방법 (파생값일 때: `~ × ~` 형식)
- [ ] xlsm 원본과 불일치하면 그 사실 명시 + 정정 대안
- [ ] 성숙도 판단 근거 (재확인 대기 · 표 미확인 등)

`PrimarySource` 의 다른 필드 (`page` · `table` · `row`) 로 표현 가능한 정보는 그쪽에 넣고 `note` 는 요약만.

---

## 금지 사항

- ❌ "TODO" · "FIXME" · "XXX" 같은 개발자 주석 표기
- ❌ 저자·사업자 개인 비판 ("잘못 알고 있음" · "실수함")
- ❌ 의견 표현 ("아마도" 대신 "추정")
- ❌ 이모지 (⚠ 만 예외, 그것도 첫 문자로만)
- ❌ 마크다운 문법 (일반 텍스트로 렌더됨)

---

## 승격·강등 규칙

값의 성숙도가 바뀌면 `note` 도 갱신:

**pending → asserted**: xlsm 유래 사실 명시 + "원문서 미조사" 를 "원문서 재확인 대기" 로
**asserted → documented**: "재확인 대기" 를 "재확인 완료" 로
**documented → verified**: 값 자체를 원문서에서 다시 확인. 유래 파생 공식 명시
**verified → asserted** (오작성 발견): 첫 문자 `⚠` 추가 + 정정 대안 명시

**주의**: 이 승격/강등은 `note` 뿐 아니라 `maturity` 필드 · `reviewedAt` 도 함께 갱신.

## 자주 쓰이는 표현 사전

| 상황 | 권장 표현 |
|---|---|
| 원문서 확인 완료 | "원문서에서 재확인 완료." |
| 확인 대기 | "원문서 재확인 대기." |
| 표 미확인 | "표·행 참조 미확인." |
| xlsm 원본 값 | "xlsm 원본 사용값." |
| 오작성 | "xlsm 원본 오작성. ..." |
| 파생 | "저자가 ... 로 파생." |
| 실측 기반 | "KDHC 지사별 실측 · 연간 공시 기준." |
| 추정 | "... 판으로 추정." |
| 정정 대안 | "xlsm-corrected 프로파일에서 자동 정정." |
| 최신 갱신 | "gir22-latest 프로파일에서 최신값 반영." |

## 감사자 관점 체크

`note` 를 다 쓴 뒤 이 3가지를 자문:

1. **감사자가 이 note 만 읽고 원문서를 찾아갈 수 있는가?** → 표·페이지·판 정보 필수
2. **감사자가 이 값이 왜 이 값인지 이해할 수 있는가?** → 파생 공식·단위 명시
3. **감사자가 재확인 필요 여부를 판단할 수 있는가?** → 성숙도·⚠ 배지 · 오작성 여부

3 개 모두 Yes 면 note 완성.
